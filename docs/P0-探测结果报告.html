P0 可行性探测结果报告

汽车之家 360° 看车内饰 · 7 个车型 URL 全量探测 · 2026-09-03

一句话结论

全部命中 A 档（最优）：7/7 车型都是 krpano 引擎，视角可读可写；机位以 krpano scene 形式存在，scene.title 就是中文机位名（驾驶位/副驾驶位/后排/中控等）；截图前只要 stopautorotate + 等 tiles 加载，同机位连拍差异可降到 0.15%，完全可以设高相似度阈值（>98%）。

1. 探测环境与方法

  • 浏览器：系统 Chrome 152 + playwright-core@1.62.1 驱动
  • Chromium 官方下载失败：storage.googleapis.com 在环境里超时，所以改用本机已装的 Chrome；通过 executablePath 指向系统 Chrome，功能完全正常。
  • 视口：1600×900，DPR=1（已锁定，批量采集必须保持同一尺寸）
  • 探测动作：打开 URL → 等待 canvas 就绪 → 注入探测脚本 → 读取 camera（hlookat/vlookat/fov）→ 可写测试 → 连拍 3 张
  • 根因验证：第一轮连拍差异 7.8~13.6%，经 stopautorotate + 12s 等待后降到 0.15%，确认为自动旋转未停 + tiles 未加载完所致。

3. 机位形态：scene.title 就是机位名

这是本次探测最有价值的一个发现：

  • krpano 的每个 scene 都有 name（如 s26in45192）和 title（如 驾驶位、后排）。
  • 切换机位 = 切换 scene，调用 K.call("loadscene(sceneName)") 或 K.loadscene(name) 即可。
  • 不同车型的 scene 总数 6~30 不等，说明车型不同，全景节点数不同；机位字典按 title 去重/归类即可。
  • 左侧边栏实际也有「驾驶位/副驾驶位/后排/中控」按钮（见下图），只是我的关键词匹配时漏了「驾驶位/副驾驶位」这种写法；但即便不点按钮，直接按 scene.title 切换也能覆盖。
图：车型 76524（奥迪A6L 2026款 2.0T quattro 尊享型）驾驶位视角；左侧边栏可见「驾驶位/副驾驶位/后排/中控」机位按钮，顶部车型名、左中「汽车之家」水印均清晰可见。

4. 复现可靠性：从 11.8% 降到 0.15%

第一轮连拍差异大 ≠ 画面不可复现，根因有两个：

  1. krpano 默认开启自动旋转（autorotate）：画面会在空闲时慢慢自转。
  2. tiles 渐进加载：第一次进入时，全景切片从高糊到清晰，前 4~8 秒画面还在变化。

根因验证数据（车型 76524）：

  • 未停转：maxDiff = 11.785%
  • 执行 stopautorotate + set autorotate.enabled=false + 等 12s 后：maxDiff = 0.15%
  • 停转后三次读相机数值：h=-1.728 / v=23.687，三次完全一致

结论：只要采集流程里加「停掉 autorotate + 等待 tiles 完全加载 + 短暂稳定」这三步，同机位复现误差 <0.2%。这意味着原方案里「视觉伺服闭环」「逐机位阈值标定」可以大幅简化——用 数值校验 为主，像素校验 设一个宽松的高阈值兜底即可。

5. 对原方案的影响

原方案设计基于 P0 实测的修正难度变化
L0 数值通道（krpano get/set）优先完全可用，7/7 通过；可直接用 hlookat/vlookat/fov 定义机位↓ 大幅下降
三级校验：L0 → L1 DOM → L2 像素大概率只用 L0 就能跑通；L2 作为兜底/审计↓ 下降
视觉伺服闭环（ORB+RANSAC+拖拽）基本可省；机位用 scene 切换 + 数值校验↓ 大幅下降
逐机位阈值标定仍需标定，但类内差异很小（<0.2%），阈值可设很高（>98%）↓ 下降
角度不收敛时回原点重来scene 切换是瞬时的，不存在拖拽收敛问题↓ 下降
截图前流程必须新增：stopautorotate + 等待 tiles 加载 + 截图新增必要步骤

6. 水印位置与合规提醒

从截图可观察到：

  • 「汽车之家」水印位于画面左中部，是大号蓝字 Logo + 「看车·买车·用车·换车」口号，覆盖车内 A 柱/左侧区域。
  • 顶部有车型名（如「奥迪A6L 2026款 2.0T quattro 尊享型」），左侧/底部有 UI 按钮。
  • 因为水印在画面中部，构图裁剪不一定能完全避开——若目标机位需要 A 柱区域，裁剪会把内饰重要部分也裁掉。
合规立场不变：不提供去除「汽车之家」水印/标识的技术实现。去标识涉及署名权、权利管理电子信息、网站用户协议、不正当竞争等多重风险。建议路径：官方授权 → 官方素材源（press kit/媒体中心）→ 自行拍摄 → 保留署名的内部研究库 → 采购图库。若仅做内部 Benchmark 研究，保留署名是安全且风险最低的用法。

7. 访问状态与鲁棒性

  • 登录态：无登录墙、无验证码、无强制登录提示
  • 反爬：当前探测 7 个 URL（间隔 1.5s）未触发验证码；批量采集时建议保持低速、低并发
  • 浮层：overlays≈6，数量可控，但截图时建议切换到清屏/隐藏 UI 模式（页面右上角有「清屏」按钮）
  • WebGL：canvas 使用 webgl，preserveDrawingBuffer=false；Playwright 截图走浏览器合成器，不受此限制

下一步建议（P1 阶段）

  1. 单车型跑通：在脚本里固化「停转 + 等待 tiles 加载 + 按 scene.title 切机位 + 数值校验 + 截图」流程。
  2. 建立机位字典：按 scene.title 把「驾驶位/副驾驶位/后排/中控」等标准化；注意同一 title 可能对应多个 scene（不同热点角度），需定义「主 scene」。
  3. 后处理策略：截图后裁掉 UI 区域（顶部车型名、底部控制点、边栏按钮），水印保留或按合规规则处理（如内部研究保留，外部使用走授权/自拍）。
  4. 批量策略：串行/低并发（1-2 并发），间隔 2-3s，避免对汽车之家服务器施压。
